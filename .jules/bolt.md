## 2024-05-24 - Zero-Server Main Thread Bottlenecks
**Learning:** In a Zero-Server Real-Time Sync architecture where the host browser acts as the central server handling concurrent student connections via WebRTC/MQTT, the main thread is highly sensitive to synchronous performance bottlenecks. Iterative DOM manipulation (O(N^2) element creation during mass join events via `.appendChild()` inside a loop without debouncing) causes layout thrashing. This blocking of the main thread can lead to dropped network packets and connection timeouts for students joining the arena.
**Action:** Always debounce rapid-fire UI updates using `requestAnimationFrame` to batch them into a single render frame, and use `DocumentFragment` to batch DOM insertions when rendering lists (e.g., lobby rosters, leaderboards), reducing O(N^2) reflow operations to O(N) detached operations + 1 reflow.
